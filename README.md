# 山岳救助ナビ（iPad PWA）

消防航空隊ヘリコプター山岳救助向けの現場誘導Webアプリです。ビルド不要（HTML / CSS / JavaScriptのみ）で、静的ホスティングにそのまま置けます。

```
rescue-nav/
├─ index.html          画面
├─ css/style.css       デザイン（昼／夜テーマ）
├─ js/geo.js           座標変換・距離/方位計算（Vincenty法・端末内で完結）
├─ js/points.js        登録地点の読み込み（Excel/CSV）・検索
├─ js/app.js           GPS・地図・ダッシュボード・テストモード・Wake Lock
├─ touroku-template.xlsx  登録地点の入力用テンプレート（データは空）
├─ manifest.json       PWA設定
├─ service-worker.js   オフラインキャッシュ
├─ icons/              アプリアイコン
├─ assets/nosleep.mp4  Wake Lock非対応時のスリープ防止用（無音動画）
└─ vendor/             地図ライブラリ（Leaflet 1.9.4・leaflet-rotate 0.6.2）、QR読み取り（jsQR 1.4.0）を同梱
```

※ iPadからGitHubにアップロードする場合は、全ファイルを1フォルダに並べた **rescue-nav-ipad.zip** を使います（末尾の付録を参照）。

## 現場座標の入力

- **度・分・秒を別々のボックスに入力**します。桁がそろうと自動で次のボックスへ進みます（緯度の度2桁 → 分2桁 → 秒「38.45」→ 経度の度3桁 → 分 → 秒）。
- 秒は小数点を打たなくても、「3845」と打てば「38.45」になります。分・秒の1桁目に6〜9を打つと、自動で「07」のように0を補います。
- 空のボックスで削除キーを押すと前のボックスに戻ります。「北緯／東経」ボタンをタップすると南緯／西経に切り替わります。
- **10進数も整数部と小数部を別のボックスに入力**できます（緯度の整数2桁 → 小数部6桁 → 経度の整数3桁 → 小数部6桁で自動的に次へ）。整数部で「.」を打つと、そのまま小数部へ移ります。小数部が6桁未満のときは、次のボックスをタップしてください。
- 度分秒と10進数のどちらかを入力すると、もう一方の入力は自動で消えます（混ざらないようにするため）。
- **名称で検索**：病院名・公園名などを入力すると、登録地点（電波不要）から即座に候補が出ます。見つからなければ「🌐 地理院」で国土地理院の地名検索（電波が必要）も使えます。候補には自機からの距離と方位（例：12.4km / 270）が表示され、タップすると目的地の候補になります。
- **地図で指定**：「🗺 地図をタップして指定」を押し、地図上の位置をタップすると緑のピンが立ちます。ピンはドラッグで微調整でき、別の場所をタップすれば置き直せます。航空写真に切り替えると、ヘリポートや着陸地点を正確に指定できます。指定中は地図が自機に追従しなくなり、確定またはキャンセルすると元に戻ります。もう一度ボタンを押すと指定をやめます。
- 検索欄には座標の文字列（例：`33.5903, 130.4206` や `33°35'25.28"N 130°25'14.35"E`）をそのまま貼り付けることもできます。
- 確定前に変換結果（10進数・度分秒）が表示され、確認ダイアログを経てから現場座標が切り替わります。検索で選んだ場合は、名称と備考も現場カードに表示されます。

## ブリーフィングソフトからのルート受け取り（QR・連携仕様 hb1）

- 救助現場カードの「**🗺 Googleマップで現場を開く**」の右にある青いボタン「**📷 QRで読み込み（ブリーフィングのルート）**」を押し（現場が未設定のときは入力画面の一番上にあります）、PC画面に出したQRコードを**iPadのカメラで枠いっぱいに**写します。読み取ると受信内容（作成日時・地点数・各地点の名称と座標）が表示され、「このルートを設定する」で反映します。
- **iPad標準のカメラアプリでは読み取らないでください。** 標準カメラから開いたリンクはSafariで開き、ホーム画面の救助ナビ（保存領域が別）には反映されません。必ずアプリ内のボタンから読み取ります。
- 反映のしかた：**救助現場（S）**＝救助現場に設定（名称付き）、**経由地（W）**＝並び順どおりに経由地として設定（今の経由地は置き換え。名前に「RP」「揚収」などがあれば立寄り点、ほかは通過点）、**出発拠点（B）**＝確認画面に表示するのみ。今の救助現場は「1つ前の座標に戻す」で戻せます。
- 経由地が11か所以上のルートは、上限（10か所）を超えるため取り込みません。
- **カメラが使えない場合**：読み取り画面の「貼り付けで読み込む」に、`hb1:…` の文字列またはQRのURL全体を貼り付けます。
- URLの `#hb1=…` でも受け取れます（Safariで開いた場合・PCでの確認用）。読み込み後、URLから自動で消えるので二重に取り込まれません。
- 検証：形式バージョン（v=1）、2地点以上、先頭が出発拠点・末尾が救助現場、緯度・経度の範囲。不正な場合は取り込まず、理由を表示します。
- ブリーフィングソフトの `config.js` の `ipadAppUrl` には、このアプリのURL（例：`https://ユーザー名.github.io/rescue-nav/`）を設定します（未設定の `hb1:…` 形式のQRでも読み取れます）。
- 初回はカメラの使用許可を求められるので「許可」を選びます。拒否した場合は「設定」→「Safari」→「カメラ」で変更できます。

## 経由地（ウェイポイント）

- 現場の手前に**最大10か所**の経由地を置き、**自機 → WP1 → WP2 → … → 現場**の順に誘導します。
- **追加**：「経由地」カードの「＋ 経由地を追加」、または入力画面の上で「＋ 経由地として追加」に切り替えます。座標入力・名称検索・地図で指定のどれでも追加でき、経路の最後（現場の手前）に入ります。
- **2つの種別**（一覧の種別ボタンで切り替え）
  - **通過点（青・丸）**：谷筋・稜線を避ける経路用。通過判定の距離（0.3／0.5／1.0km、初期値0.5km）に入ると、自動で次へ進みます。
  - **立寄り点（橙・角）**：揚収・ランデブーポイント用。近づいても自動では進まず、「到着圏内」と表示され、**地図の右下に大きな「次へ ▶」ボタン**が出ます。作業が終わったらこれを押すと、次の経由地（または現場）へ切り替わり、ボタンは消えます。
  - 登録地点（場外一覧表）から選んだ地点や、名前に「RP」「揚収」「場外」「ヘリポート」を含む地点は、最初から立寄り点になります。
- **誘導の表示**：方位リングの青い札（例：WP1 036）と、ダッシュボードの距離・方位・ETEは**次の経由地**を示します。距離の下に「現場まで（経由地経由）合計 20.1 km ／ ETE」を表示します。
- **地図**：自機から次の経由地までを赤の太線、その先の経路を赤の破線で表示します。完了した経由地は灰色になります。
- **操作**：「◀ 前へ」「次へ ▶」「現場へ直行」（残りの経由地をとばす）。一覧では、▶（この経由地から誘導し直す）、▲▼（順番の入れ替え）、✕（削除）、名前のタップ（名前の変更）ができます。
- 経由地は現場を変更しても残ります。不要になったら「すべて削除」を押します。
- 「現場周辺の地図を保存」では、経由地の周辺（半径約1km）と経由地を回るルート沿いも保存します。

## 登録地点（場外一覧表）

- 九州協定の協議会一覧を、担当者が「名称・緯度・経度・備考」などに整理し直してアプリに読み込みます。データは**このiPadの中だけ**に保存され、外部には送信されません。GitHubにも置きません。
- **入力用テンプレート**：アプリの「登録地点」→「入力用テンプレートを保存」で取り出せます（県ごとのシート、見出し：番号／名称（必須）／種別／緯度（必須）／経度（必須）／備考）。必須の列は見出しが赤、任意の列は青です。見出しの「（必須）」は消しても読み込めます。
- **見出しの名前と列の順番は多少違っても読めます**（例：「施設名称」「No.」「座標」）。シート名に県名を入れると、県ごとに分類されます。「記入方法」「説明」などのシートは読み込みません。
- **座標の書き方**：10進数（33.590355）、度分秒（33°35'25.28"、33 35 25.28、33度35分25.28秒）のどれでも可。緯度経度を1列にまとめる場合は見出しを「座標」に。
- **更新手順**：①Numbersで編集 →「書き出す」→「Excel」→「"ファイル"に保存」 ②アプリの「一覧表を読み込む」でそのファイルを選ぶ ③県別件数・前回との比較・エラー行を確認して「入れ替える」
- **エラー表示**：座標が空欄・読めない行は登録されず、シート名と行番号が表示されます。緯度経度の入れ違いは自動で直し、九州の範囲外や重複の疑いは「確認が必要な行」として表示します。
- **元に戻す**：「前の一覧に戻す」で1回分だけ元に戻せます。
- **2台目のiPad**：同じExcelファイルをAirDropで送り、2台目でも「一覧表を読み込む」を行ってください。取り込み後、受け取ったファイルは削除してください。
- **バックアップ**：「一覧をCSVで書き出す」で、現在の一覧をCSV（Numbersで開ける）として保存できます。正本のファイルを失った場合の復元に使えます。
- ⚠ ホーム画面のアイコンを削除したり、Safariの「履歴とWebサイトデータを消去」を行ったりすると、登録地点も消えます。その場合は一覧表を読み込み直してください。

## 地図の見方（ナビ表示）

- 自機は常に**画面中央より少し下**（上から約64%の位置）に表示され、前方を広く見渡せます。
- 自機を中心に**方位リング**を表示します。目盛りは5°・10°ごと、数字は**30°ごと**（30〜360、**北＝360**）で、90・180・270・360は黄色です。
- リング外側の**赤い三角と「現場 270」**が、現場への指示方位です。黄色の点線は自機の現在の進行方位です。現場の上空で捜索している間も、赤い三角と方位の札は**常に表示**されます。真上（10m以内）では方位が定まらないため、札は「**現場 直上**」と表示し、赤い三角は直前の方位に残します。
- **「機首方向が上」**（初期設定）：進行方向が常に画面の上になるよう地図が回転します（5kt未満のホバリング中は向きを固定）。**「北が上」**に切り替えると、360が常に画面の上になります。
- **「Googleマップで現場を開く」**は、Googleマップのアプリを直接起動します（アプリ内ブラウザを経由しないので、戻ったときに白い画面は出ません）。初回は「“Google マップ”で開きますか？」と聞かれるので「開く」を選びます。Googleマップアプリが入っていない場合は、Appleマップで開くか確認します。
- **「全体表示」**：自機・**残りの経由地**・現場がすべて画面に収まるように縮尺を合わせます。「機首方向が上」で地図が回転していても、右側のボタンや「現在位置に戻る」ボタンに隠れない位置に収めます（完了した経由地は含みません）。
- **空域の参考表示**：地図右側の「**空域 表示 ON/OFF**」で、国土交通省航空局のデータ（地理院地図で公開）による空域を重ねて表示します。初期表示は **管制圏・情報圏（青）・進入管制区（紫・破線）・特別管制区（赤）・民間訓練試験空域（橙・点線）** の4つで、**空港等の周辺空域（ドローン用の制限表面・緑）** は必要なときにパネルでオンにします。地図の回転（機首方向が上）にも追従します。
  - 地図上の空域をタップすると、その地点にかかっている空域の種類を地図下部のカードに表示します（12秒で自動的に閉じます）。
  - データは九州全域を端末に保存しておけば電波がなくても表示できます。パネルの「九州全域の空域データを保存」で保存でき、電波があるときは2週間ごとに自動で保存し直します（このデータはアプリ終了時も消しません）。
  - ⚠ **参考表示**です。表示できるのは水平方向の範囲で、誤差を含む場合があります。正確な空域・高度は AIP・航空図・管轄の管制機関で確認してください。地理院地図の外での利用条件は、国土地理院・航空局に確認することをおすすめします。
- 地図は**ドラッグで自由にスクロール**できます。ドラッグすると自機の追従が止まり、左下に **「◎ 現在位置に戻る」** ボタンが出ます。タップすると元のナビ表示に戻ります。
- 方位の数字はすべて北＝360の3桁表記（例：西＝270、北＝360）です。

## 1. Windows PCでのローカル動作確認

1. このフォルダでコマンドプロンプト（または PowerShell）を開きます。
2. 次のどちらかでローカルサーバーを起動します。
   - Python がある場合：`python -m http.server 8000`
   - Node.js がある場合：`npx serve -l 8000`
3. Chrome または Edge で **http://localhost:8000** を開きます。
   - `localhost` は安全なコンテキストとして扱われるため、GPS（位置情報）や Service Worker も動きます。
   - PCにはGPSがないため、右上の **「テストモード」** で模擬移動を確認してください。テスト中は「↺ 最初からやり直す」で開始位置・経由地の通過状況を元に戻せます。テストモードを終了すると模擬位置はクリアされ、経由地の通過状況もテスト前に戻ります。
   - Chrome DevTools（F12）→「⋮」→ More tools → **Sensors** で任意の位置を擬似的に設定することもできます。

> ⚠ `index.html` をダブルクリックして直接開く方法（file://）では、Service Worker と位置情報が動きません。必ずサーバー経由で開いてください。

## 2. iPad実機への配信（HTTPS必須）

GPSはHTTPSでないと使えません。以下のどれかで配信します。

### A. GitHub Pages（おすすめ・無料）
1. GitHubで新しいリポジトリを作り、このフォルダの中身をそのままアップロード（「Add file → Upload files」でドラッグ＆ドロップ可）。
2. リポジトリの **Settings → Pages** → Source を「Deploy from a branch」、Branch を `main` / `/(root)` にして Save。
3. 1〜2分後に `https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます。

### B. Cloudflare Pages
1. Cloudflareダッシュボード → **Workers & Pages → Create → Pages → Upload assets**。
2. このフォルダをドラッグ＆ドロップしてデプロイ。`https://<プロジェクト名>.pages.dev/` で公開されます。

### C. 公開せずにPCから一時的に試す
`cloudflared tunnel --url http://localhost:8000` を実行すると、一時的な `https://xxxx.trycloudflare.com` のURLが発行されます。iPadからそのURLを開いて試せます。

### iPad側の設定
1. Safariで公開URLを開き、位置情報の許可を求められたら「許可」。
2. 共有ボタン →「**ホーム画面に追加**」。以後はホーム画面のアイコンから全画面で起動します。
3. 「設定」→「プライバシーとセキュリティ」→「位置情報サービス」→ **Safari Webサイト** を「使用中のみ許可」、**正確な位置情報** をオン。
4. 念のため「設定」→「画面表示と明るさ」→「自動ロック」を **なし** にしておくと確実です。

## 3. 運用上の注意（重要）

- **Wi-Fiモデルの iPad にはGPSがありません。** 上空ではWi-Fi測位ができないため、**Cellularモデル**（GPS/GNSS内蔵）を使うか、外付けGNSSレシーバー（Bluetooth接続でiOSの位置情報に反映されるもの）を使ってください。
- **出動前に一度オンラインで起動**してください。アプリ本体と地図ライブラリが端末に保存され、以後は電波がなくても距離・方位・ETEの計算が動きます。
- 地図は、一度表示した範囲が端末に一時保存されます。現場が分かったら地上で **「現場周辺の地図を保存」** を押すと、**地理院 標準地図と航空写真の両方**について、現場の半径約3km（ズーム10〜16）・経由地の周辺・現在地からのルート沿いを保存します（OSMは利用規約により一括保存不可）。
- **保存した地図はアプリ終了時に削除**されます。iPadは終了を確実に知らせないため、終了の通知が来ればその場で、来なかった場合は**次回起動時に**削除します。ただし、**前回の使用から2時間以内の再起動では削除しません**（飛行中にGoogleマップへ切り替えている間などに、iPadが裏でアプリを閉じて再起動した場合に、地図が消えないようにするため）。
- **標高**は現場座標の確定時に国土地理院APIから取得します。通信できない場合は「失敗」と表示され、電波が戻ると自動で再取得します（「再取得」ボタンもあります）。
- **GPS高度**は誤差を含む目安です（垂直精度 ±◯m を併記）。航空機の高度計の代わりにはなりません。
- 方位は**真方位**です（磁方位ではありません）。
- **画面ON維持**：Screen Wake Lock APIを使います（ホーム画面から起動したアプリでは iPadOS 18.4 以降で有効）。非対応時は無音動画を使う方式に自動で切り替わります。上部の表示が赤い場合はタップして有効にしてください。

## 4. 更新方法

ファイルを修正したら `service-worker.js` の `CACHE_VERSION`（例：`v1.0.0` → `v1.0.1`）を上げてから再デプロイしてください。iPadでアプリを開き直すと「新しいバージョンがあります」と表示され、再起動で反映されます。

## 5. 同梱ライブラリとライセンス

- `vendor/leaflet/`：Leaflet 1.9.4（BSD-2-Clause）
- `vendor/leaflet-rotate/`：leaflet-rotate 0.6.2（**GPL-3.0**）— 地図の回転（機首方向が上）に使用
- `vendor/jsqr/`：jsQR 1.4.0（Apache-2.0）— アプリ内カメラでのQR読み取りに使用

空域データ：国土交通省航空局（国土地理院 地理院地図で公開）

いずれも `vendor/` 内に LICENSE を同梱しています（iPad用の1フォルダ版では `LICENSE-*.txt`）。leaflet-rotate はGPL-3.0のため、アプリを外部に配布する場合はGPLの条件（ソースコードの提供など）に従ってください。隊内での利用だけなら通常は問題ありません。leaflet-rotate を読み込めない場合も、地図は「北が上」で動作します。

## 付録：iPadだけでGitHub Pagesに公開する手順

iPadのSafariではフォルダ階層ごとアップロードできないため、全ファイルを1フォルダに平らに並べた **rescue-nav-ipad.zip**（21ファイル）を使います。

1. **zipを展開**：zipを「ファイル」Appに保存し、タップして展開（フォルダ `rescue-nav-ipad` ができる）。
2. **GitHubアカウント作成**：github.com →「Sign up」。ユーザー名は公開URLの一部になる（英小文字推奨）。
3. **リポジトリ作成**：右上「＋」→「New repository」。名前 `rescue-nav`、**Public**、READMEなどは追加しない →「Create repository」。
4. **アップロード**：「uploading an existing file」→「choose your files」→「ファイルを選択」→ 展開したフォルダで「選択」→ 全21ファイルを選んで「開く」→「Commit changes」。
5. **Pages有効化**：「Settings」→「Pages」→ Source「Deploy from a branch」、Branch「main」「/(root)」→「Save」。数分後 `https://<ユーザー名>.github.io/rescue-nav/` で公開。
6. **ホーム画面に追加**：SafariでURLを開き位置情報を「許可」→ 共有ボタン →「ホーム画面に追加」。
7. **iPad設定**：位置情報サービス → Safari Webサイト「使用中のみ許可」・正確な位置情報オン。自動ロック「なし」推奨。
8. **更新時**：変更したファイルだけ「Add file」→「Upload files」で上書き → アプリを2回開き直すと反映。

※ GitHubの画面が崩れる・ボタンが見つからない場合は、アドレスバー左の「ぁあ」（または「AA」）→「デスクトップ用Webサイトを表示」。
※ iPad mini 7 の **Wi-Fiモデルには GPS がありません**（Wi-Fi + Cellular モデルのみ内蔵）。
